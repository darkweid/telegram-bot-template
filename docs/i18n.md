# Translations

How the bot speaks more than one language: how strings are marked in the code,
how the reply language is chosen, how the gettext catalogs are kept in step with
the code, and what a new language needs. Open it when writing any text a user
sees, after changing one, or when adding a language. The bot ships English and
Russian; the catalogs live in `locales/<locale>/LC_MESSAGES/messages.po`.

## Marking strings

The msgid is the English text itself; the English catalog may leave its
translations empty. Mark strings with the helpers from `aiogram.utils.i18n`:

```python
from aiogram.utils.i18n import gettext as _, ngettext

await message.answer(_("Note saved. Send /notes to see all of them."))

header = ngettext(
    "Summary of {count} recent note:",
    "Summary of {count} recent notes:",
    result.note_count,
).format(count=result.note_count)
```

- `_` translates at once, into the locale of the current update.
- `ngettext` picks the plural form for a number; Russian has three.
- `lazy_gettext as __` translates when the value is rendered, for a string
  built before a locale is active; extraction picks it up.
- `N_` from `src.core.i18n` only marks a string for extraction and returns it
  unchanged. It is for a msgid stored ahead of time and translated later: an
  exception's `message_key`, a command description in `src/note/commands.py`,
  the titles in `src/broadcast/texts.py`.

Placeholders are named (`{count}`) and filled with `.format()` after
translation, so a translator can move them. A reply is HTML, so a value the
user controls goes through `aiogram.html.quote`, or the template is filled with
`format_html` (`src/core/errors/exceptions.py`), which escapes every field.

**The reply language.** `UserLocaleMiddleware` (`src/core/i18n/middleware.py`)
picks it for every update, the first that has a catalog:

1. the language the user chose with `/language`, stored in `users.locale`;
2. the language Telegram reports for the user (`language_code`; only the
   language part counts, so `en-US` picks `en`);
3. `DEFAULT_LOCALE` (`en`), which must be one of the supported locales.

The error handler is the exception: it runs outside the middlewares and answers
in the Telegram language (see [errors and alerts](bot-layer.md#errors-and-alerts)).

**Text outside an update.** A task has no current locale, so `_` cannot be
used there. Keep the msgid in an `N_` constant, resolve each recipient's locale
from the stored user with `resolve_locale`, translate with
`i18n.gettext(msgid, locale=...)` and fill the result with `format_html`.
`NotifyAdminsOfNewUserUseCase` (`src/user/usecases/notify_admins.py`) does
exactly this for every admin. Code that renders several strings at once wraps
them in `with i18n.context(), i18n.use_locale(locale):` and uses `_` inside, as
the broadcast report does (`src/broadcast/usecases/run_broadcast.py`).

## Updating catalogs

After adding, changing or removing any marked string:

```bash
make i18n-update    # extract the messages and merge them into every catalog
# translate the new entries in locales/ru/LC_MESSAGES/messages.po
make i18n-compile   # build the .mo files the bot loads
```

`make i18n-update` scans `src/` (`babel.cfg`), merges without fuzzy matching,
drops obsolete entries and normalizes the files, so running it twice changes
nothing. Commit the `.po` files. The `.mo` files are build output and ignored by
git: `make run-dev` compiles them before starting, the production image
compiles its own (`infra/docker/Dockerfile`), and the tests compile the working
tree into a temporary directory. In the running dev stack, run
`make i18n-compile restart s=bot` after editing a catalog.

`build_i18n` (`src/core/i18n/__init__.py`) refuses to start without a compiled
catalog for every supported locale, so a missing `.mo` fails at startup instead
of showing untranslated replies.

`make test` runs the catalog tests (`tests/unit/locales/test_catalogs.py`).
They fail when:

- a catalog holds other messages than the code, missing or left over;
- a catalog has fuzzy entries;
- a translation drops or renames a placeholder;
- the Russian catalog leaves a message untranslated or does not declare three
  plural forms.

## Adding a language

German as the example:

1. `make i18n-init LOCALE=de` starts `locales/<locale>/LC_MESSAGES/messages.po` from
   the code's current messages.
2. Add `"de"` to `SUPPORTED_LOCALES` in `src/core/locales.py`.
3. Add the language's own name to `LANGUAGE_NAMES` in `src/user/keyboards.py`,
   for example `"de": "Deutsch"`. The `/language` keyboard shows every language
   in its own name, never translated.
4. Add its English name to `RESPONSE_LANGUAGES` in `src/note/prompts.py`, for
   example `"de": "German"`: the summary prompt tells the model which language
   to answer in.
5. Translate the catalog and run `make i18n-compile`.

`make test` then checks the new language: `tests/unit/src/user/test_keyboards.py`
fails while a supported language has no name in `LANGUAGE_NAMES`,
`tests/unit/src/note/test_prompts.py` while it has none in
`RESPONSE_LANGUAGES`, and the catalog tests cover the new catalog's messages,
fuzzy entries and placeholders. Only the Russian catalog is checked for
completeness, so read the new one for untranslated entries yourself.

Nothing else changes: the command menus are published for every supported
language on each start, and once the bot runs with the new catalog a user
whose Telegram language is German gets German replies.
